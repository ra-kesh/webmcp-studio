# Production-readiness backlog

## Priority and effort

- **P0:** blocks the claimed demo or creates unacceptable data, security, accessibility, or trust failure.
- **P1:** required for a credible beta document/image editor.
- **P2:** important quality, depth, and scale work after core integrity.
- **P3:** later differentiation or enterprise depth.
- **XS:** less than 1 engineer-day.
- **S:** 1-2 engineer-days.
- **M:** 3-5 engineer-days.
- **L:** 1-2 engineer-weeks.
- **XL:** more than 2 engineer-weeks or cross-service program.

Effort is a realistic engineering class including tests, not elapsed calendar time or a commitment.

## First seven independently shippable slices

1. **Published render repair:** DEMO-01 plus the narrow contract tests needed to keep it fixed.
2. **Command integrity:** CMD-01, Select/`V`, platform shortcuts, and review/history enablement projection.
3. **Safe review mode:** REVIEW-01 with exhaustive mutation-state tests.
4. **Responsive action parity:** RESP-01 and A11Y-01, without redesigning the rest of the editor.
5. **Reachable pages/outputs:** PAGE-01 using the existing domain commands, followed by removal of dead parallel UI.
6. **Strict publish gate:** VALID-01 plus version/import relation fixtures.
7. **Clean demo gate:** E2E-01 exercising the real published artifact.

Only after these slices should the team begin template catalog, media repository, or richer text work. Adding breadth before command and validation integrity will multiply contradictory states.
