# Figma depth and Canva ease: feature-parity matrix

Status vocabulary:

- **Working:** behavior completed the exercised path and matched its label.
- **Partial:** useful behavior exists but is materially incomplete.
- **Misleading/no-op:** control appears available but does not perform a valid user-visible mutation.
- **Broken:** exercised path fails.
- **Absent:** no reachable behavior was found.
- **Unreachable:** implementation exists but is not mounted in the product shell.

This matrix uses current official [Figma editor documentation](https://help.figma.com/hc/en-us/articles/15297425105303-Explore-design-files), [Figma Layers guidance](https://help.figma.com/hc/en-us/articles/360039831974-View-layers-and-assets-in-the-Layers-Panel), [Figma Properties guidance](https://help.figma.com/hc/en-us/articles/360039832014-Design-Prototype-and-view-Code-in-the-Properties-Panel), [Canva template discovery](https://www.canva.com/templates/), [Canva editing guidance](https://www.canva.com/help/editing-designing/), and [Canva keyboard shortcuts](https://www.canva.com/help/canva-keyboard-shortcuts/) as behavioral benchmarks. The target is not feature-for-feature cloning. It is Figma-like interaction integrity plus Canva-like time to first useful result for documents and images.

## Summary

The product has enough working primitives to justify continued investment. It does not have enough shared semantics to safely add more surface area. The next feature should not be another toolbar control. The next feature is the command, capability, transaction, and validation substrate that makes every existing control truthful.
